## 二、系统拓扑

```
http://jwxt.cupl.edu.cn/eams/homeExt.action
        │ 302
        ▼
/eams/localLogin.action        ← EAMS 本地登录（学号/工号 + 密码，SHA1 加盐）
        │ 未登录访问业务页
        ▼
https://ca.cupl.edu.cn/tpass/login?service=<原URL>   ← 「智慧法大」统一认证
        │ 登录成功，CAS 回调
        ▼
EAMS 建立自己的 session → 可访问成绩页
```

实测：统一认证密码在 `localLogin` 报「密码错误」，说明两套账号库不同步。**生产只走 tpass。**

## 三、EAMS 本地登录（探测过，但不采用）

- `GET /eams/homeExt.action` → 302 → `/eams/localLogin.action`
- 页面内脚本：`form['password'].value = CryptoJS.SHA1('<每次随机 UUID>-' + 明文)`
- 关键点：salt **每次刷新都变**，必须在同一会话内先取页面再提交
- `POST /eams/localLogin.action`，字段 `username` / `password`(40 位 hex)
- 毫秒级连续提交会返回 **「请不要过快点击」**；人工间隔 3 秒以上才放行
- 判定只能看页面文本，HTTP 状态码恒为 200

## 四、统一认证 tpass（生产采用）

### 4.1 登录流程

```
1. GET  https://ca.cupl.edu.cn/tpass/login?service=<urlencoded 目标>
        → 拿 lt 令牌（LT-xxxx-tpass）与 JSESSIONID

2. POST https://ca.cupl.edu.cn/tpass/rsa
        → {"publicKey": "MFwwDQYJKoZIhvcNAQEBBQADSwAwSAJB..."}   # Base64 的 DER(SPKI)

3. ul = base64(RSA_PKCS1v15(username))
   pl = base64(RSA_PKCS1v15(password))

4. POST https://ca.cupl.edu.cn/tpass/login?service=<同上>
        ul / pl / lt / execution=e1s1 / _eventId=submit / choosenumber=学号

5. 302 → http://jwxt.cupl.edu.cn/eams/homeExt.action;jsessionid=...
        → EAMS session 建立完成
```

### 4.2 加密实现

- 公钥是 SPKI DER，解析出 `modulus` / `exponent`（实测 `e=65537`，512 位）
- PKCS#1 v1.5 填充 + `pow(m, e, n)` + Base64
- 只需标准库 `pow` 与手写 DER 解析，**不依赖 cryptography / rsa**
- 代码见 `src/tpass_auth.py`，单测覆盖公钥解析与密文长度

### 4.3 成功判据

- 最终 URL 回到 `jwxt.cupl.edu.cn`
- 页面不再含 `id="loginForm"`
- 失败特征：`用户名或密码错误` / 仍停留在 `/tpass/login`

## 五、成绩接口

### 5.1 真实地址

```
POST /eams/teach/grade/course/person!historyCourseGrade.action?projectType=MAJOR
（无 body）
```

这个接口对应页面上的 **「所有学期成绩」**（toolbar 点击后 AJAX 局部刷新）。
默认的 `person.action` 只显示当前学期，且**没有分数列**（只有最高/最低/平均分），不能用于监控。

### 5.2 表格结构

表格 `class="gridtable"`，21 列：

```
学年度-学期 | 课程号 | 课程序号 | 课程名称 | 课程英文名称 | 课程属性 | 学分
过程性成绩1..5 | 期末成绩 | 总评成绩 | 最终 | 绩点
最高分 | 最低分 | 平均分 | 选课人数 | 课堂成绩排名
```

真实数据示例：

```
2024-2025-2 | 401090032 | 401090032.01 | 法学基本理论 | ... | 限选 | 2
| 100 | 98 | -- | -- | -- | 98 | 98 | 98 | 6.3 | 99 | 96 | 97.73 | 33 | 4
```

### 5.3 解析要点（踩过的坑）

1. **必须精确匹配表头**。最初用包含匹配，`课程号` 抢走了 `课程名称`，`过程性成绩1` 抢走了 `总评成绩`，导致解析出 42 条且分数全错。
2. 修正为「精确优先 → 包含匹配 + 排除噪声列」，结果 **45 条全部正确**。
3. `总评成绩` 为 `--` 表示**尚未出分**，必须跳过——否则「课程已排课但没分」会被误判成新增成绩。
4. 不能静默返回空列表：表格缺失或列不匹配要抛 `GradeParseError`，触发「监控失效」告警。

## 六、验证码与风控

- 登录页当前**没有**验证码输入框
- 页面保留 `refreshCaptcha` 与 `/eams/captcha/image.action`
- GitHub Actions 与云厂商 IP 段可能更容易触发风控；策略是：10 分钟频率 + 0～240 秒随机错峰 + 单账号串行 + 失败退避
- 一旦出现验证码：告警并停止，不自动识别

## 七、GitHub Actions 出口连通性

本机（公网）已确认可达，但 **runner 是境外 Azure 出口，尚未实测**。

验证方式：fork 后手动触发 `.github/workflows/connectivity-check.yml`。它会检查：

1. `jwxt` 登录页是否 200
2. 登录页是否含 salt
3. 是否能取到 tpass 的 `publicKey`

全 PASS 才建议继续用 Actions；有 FAIL 则退回国内云函数或本机计划任务（见 `故障排查与回退.md`）。

## 八、对实现的最终约束

- 每次运行重新取 `lt` 与公钥，不缓存
- 单次运行只登录一次，失败立即退出，绝不在 CI 里循环重试
- 成败按页面文本判定，不看状态码
- 快照只存 `SHA-1(学期|课程名)` 前 16 位，不存分数
- 页面结构变化必须告警，不能静默
