# 故障排查与回退

## 一、先看错误类型

程序把失败分成几类，日志里会直接写出原因：

| 异常 | 日志关键字 | 含义 | 能否自愈 |
| --- | --- | --- | --- |
| `CredentialError` | 用户名或密码错误 | 账密不对 | 否，需改 Secret |
| `CaptchaRequiredError` | 需要验证码 | 触发了风控验证码 | 否，需人工 |
| `RateLimitedError` | 请不要过快点击 | 提交过快被拦截 | 是，退避后恢复 |
| `SessionExpiredError` | 登录态失效 / 被统一认证接管 | SSO 会话异常 | 多数能，重跑即可 |
| `PageChangedError` | 未找到成绩表格 / 结构需更新 | 页面改版 | 否，需改解析 |
| `ConfigError` | 缺少 XXX | Secret 没配或拼错 | 否 |
| 网络异常 | `ConnectionError` / `Timeout` | 出口被拦或系统维护 | 看情况 |

告警策略：凭据错误、验证码、页面改版**立即**发告警；限流和会话失效**连续 2 次**才告警，避免刷屏。

## 二、按场景处理

### 1. GitHub Actions 访问不了教务系统

**现象**：日志里全是超时，或 `connectivity-check` 红叉。

**先跑一次自检**：Actions → **连通性自检** → Run workflow。它会检查三件事：

- `jwxt` 登录页是否可达
- 登录页是否含 salt
- 是否能拿到 tpass 的 RSA 公钥

三项全 PASS 说明出口没问题，问题在账密或解析；有 FAIL 说明这台 runner 被学校 WAF 拦了。

**已实测的结论（2026-11-06）**：境外 runner 上 `jwxt:80` 恒为 `ConnectTimeout`，
而同一轮里 `tpass:443` 与 RSA 公钥接口都 PASS —— 是目标侧拒绝了境外 IP 的 80 端口，
不是 runner 断网。因此本项目**已把 `grade-check.yml` 的 `cron` 注释掉**，
定时改由本机计划任务执行，完整步骤见 [本机计划任务.md](本机计划任务.md)。

**方案 A：本机计划任务（现已采用）**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\local_task.ps1 -Action install -IntervalMinutes 10
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\local_task.ps1 -Action status
```

别把间隔设成 1 分钟——同一 IP 反复登录更容易触发风控。

**方案 B：国内云函数**（腾讯云 SCF / 阿里云 FC）

把 `src/` 与 `requirements.txt` 打包上传，定时触发器设 10 分钟，环境变量照 Secrets 配。
两点注意：云厂商出口 IP 段同样可能被拦，先跑 `scripts/connectivity_check.py` 验证；
快照文件在云函数里不持久，需要挂 COS / OSS 或改成数据库，否则每轮都会被判成「首次运行」而不推送。

### 2. 出现验证码

目前登录流程**不触发**验证码。如果哪天出现：

- 程序会抛 `CaptchaRequiredError` 并发告警，不会尝试自动识别；
- 处理方式：降低频率（10 分钟 → 30 分钟）、错峰（避开整点）、或暂停一段时间；
- **不要**接入打码平台——那属于绕过学校安全措施。

### 3. 页面改版导致解析失败

**现象**：`PageChangedError: 找到表格但未匹配到「课程 + 成绩」列`。

**定位**：

```powershell
python src\monitor.py --dry-run -v
```

日志会显示抓到的字符数。把页面存下来对照表头：

```powershell
python -c "import sys;sys.path.insert(0,'src');from tpass_auth import TpassClient;c=TpassClient('学号','密码');c.login();open('page.html','w',encoding='utf-8').write(c.fetch_history_grades())"
```

打开 `page.html` 搜「课程名称」「总评成绩」，把新表头加进 `src/grade.py` 的 `_HEADER_ALIASES` 即可。

解析器设计上**不会静默返回空列表**：结构不符一定抛异常并告警，避免「监控看起来在跑，其实早就失效」。

### 4. Actions 到点没运行

- GitHub 的 `schedule` **不保证准时**，高峰期可能延迟 10～30 分钟，甚至跳过某次；
- 仓库连续 60 天无提交，定时任务会被自动暂停：随便提交一次，或手动 Run 一次即可恢复；
- 需要更准时，只能改用云函数或本机计划任务。

### 5. 额度超限

- Public 仓库：Actions 免费，不限分钟数；
- Private 仓库：每月 2000 分钟。10 分钟一次、每次约 40 秒，约 200～400 分钟/月，够用；
- 如果改成了 5 分钟一次又跑 Private，可能触顶——把 cron 改回 `*/10` 或 `*/15`。

### 6. 收不到通知

**电脑通知（默认渠道）**：

1. 先单独验证调用是否成功：
   ```powershell
   python -c "import sys;sys.path.insert(0,'src');import notify;print(notify.toast('测试','通知通道自检'))"
   ```
   输出 `True` 说明调用成功；输出 `False` 或日志里有 `系统通知发送失败` 则是系统层拦截；
2. 检查 Windows 设置 → 系统 → 通知：允许通知、关闭「专注助手」、找到 **Windows PowerShell** 放行；
3. 还不行就把设置里的**强提醒**勾上——置顶弹窗不依赖系统通知；
4. 注意首次建立基线与「无新增」本来就不发通知。

**钉钉 / 飞书（可选渠道）**：

1. 日志里有没有 `通知发送成功`？没有则看 `code=` 与 `errmsg=`；
2. 钉钉 `errcode=310000`：加签错或关键词不匹配；
3. 飞书 `code=19021`：签名校验失败；
4. 机器人是否被移出群；
5. 本机跑 `python src\monitor.py --test-notify` 单独验证。

### 7. 改了密码之后

只改一个地方：本机 `config\.env`（或 GitHub 的 `CUPL_PASSWORD` Secret）。不用重新建仓库，也不用清空快照。

## 三、手动控制开关

| 需求 | 做法 |
| --- | --- |
| 暂停监控 | 桌面版点「暂停监测」／`local_task.ps1 -Action remove` |
| 临时只验证不推送 | `python src\monitor.py --dry-run` |
| 清空基线重新开始 | `python src\monitor.py --reset-state` |
| 换通知渠道 | 改 `NOTIFY_CHANNEL`（desktop / none / dingtalk / feishu） |
| 开关强提醒 | 改 `NOTIFY_STRONG`（1 / 0） |
| 调整频率 | 桌面版设置里改间隔；计划任务用 `-IntervalMinutes` |
| 指定成绩页地址 | 设 `CUPL_GRADE_URL`（默认已用 `historyCourseGrade`） |
