# 可实行方案对比与选型

## 一、五种形态

| 方案 | 使用门槛 | 成本 | 时效 | 凭据风险 | 负载与扩展性 | 传播友好度 |
| --- | --- | --- | --- | --- | --- | --- |
| **A 单人 Actions 自助监控** | 会填 5 个 Secret | 免费 | 5～15 分钟 | 低（仅本人） | 单账号，O(1) | 低 |
| **B GitHub 模板仓库 fork 即用** | fork → 填 Secret → 启用 → 测试 | 免费，零服务器 | 同 A | **低**：Secret 不随 fork 继承，天然隔离 | 请求分散在各自 runner | **高**：一个链接就能扩散 |
| **C 零凭据公开公告监控 + 群广播** | 进群 / 加机器人，**不用账号** | 免费 | 取决于公告发布 | **无**（不收集账号） | **O(1) 抓取、广播 N 个群** | **最高** |
| **D 中心化托管 + 网页配置向导** | 填网页表单即可 | 服务器 + 域名 + 运维 | 最优 | **最高**：服务端代管明文密码 | N 个账号同 IP 高频登录，易触发风控 | 高但风险大 |
| **E 端侧工具（桌面托盘 / 浏览器扩展）** | 装一个客户端 | 免费 | 本地可控 | 极低（凭据不出本机） | 需设备常开 | 中 |

## 二、为什么不能简单地「做一个网站替所有人查」

最直觉的做法是搭个服务器，用户填学号密码，后台统一轮询。它有两个绕不过去的硬伤：

1. **风控**。教务系统会把同一出口 IP 的登录行为关联起来。N 个账号从同一批云 IP 每 5 分钟登录一次，很容易触发验证码、限流甚至封禁，而且是**单点故障**——一台机器被拦，所有用户同时失效。
2. **凭据**。统一认证虽然在前端用 RSA 加密密码，但那只是防抓包，**服务端仍然必须拿到明文才能登录**。代管他人的教务密码，安全责任与合规风险都无法消除。

所以负载和凭据风险都不能随用户数线性增长，只能分层。

## 三、推荐的分层架构

```
L0 零凭据层（方案 C）
   只抓公开公告页一次 ──► 广播给 N 个订阅群
   抓取量 O(1)，与用户数无关；不接触任何账号

L1 自助分发层（方案 B，本项目主线）
   每个用户 fork 一份 ──► 用自己的 Secrets ──► 在自己的 runner 上跑
   请求天然分散，无共享服务器、无共享凭据、无跨用户数据

L2 可选托管层（方案 D，默认不实现）
   仅当「连 GitHub 账号都没有」成为真实瓶颈时再考虑
   必须配套：凭据加密、单账号限流、错峰、一键撤销、免责声明
```

### 各层的能力边界

| 层 | 能回答的问题 | 不能回答的问题 |
| --- | --- | --- |
| L0 | 「最近有成绩发布吗」 | 「**我**的某一科出分了吗」 |
| L1 | 「**我**哪几科出了分、多少分」 | 「别人出了吗」（也不应该回答） |
| L2 | 同 L1，但零配置 | —— 代价是凭据托管 |

## 四、选型结论

**主线：A → B。** 先让自己能用（A），再把配置外置、文档补齐，变成别人 fork 就能用的模板仓库（B）。这也是本项目当前的状态。

**传播层：C。** 对「广泛传播且简单易用」这个诉求，真正的答案不是把 L1 做成网站，而是补一个**不需要任何账号**的公告层：抓 `jwc.cupl.edu.cn` 等公开页面，一有新公告就广播到所有订阅群。它的抓取量与用户数无关，且完全不接触账号，适合做成「扫码进群就能用」的入口。代价是只能提示「某批成绩发布了」，无法精确到个人科目。

**D 默认不做。** 只有当用户规模大到「连 fork 都不愿意」时才有意义，且必须解决凭据托管与出口 IP 分散问题。

**E 作为未来形态。** 桌面托盘 / 浏览器扩展能做到「凭据不出本机 + 秒级」，但分发与保活成本高。

## 五、降负载的统一策略

无论哪一层，都要遵守同一套约束：

- 出分季启用，非出分季降频或直接停用；
- cron 内随机 `sleep 0~240s` 抖动错峰，避免整点集中；
- 同一仓库用 `concurrency` 防叠加运行；
- 登录失败指数退避，单账号串行，绝不并发登录；
- 页面文本异常即告警，不静默重试。

## 六、成本对照

| 方案 | 月度成本 | 说明 |
| --- | --- | --- |
| A / B | 0 元 | Public 仓库 Actions 免费；Private 每月 2000 分钟，10 分钟频率约需 200～400 分钟 |
| C | 0 元 | 一个定时任务 + N 个 Webhook |
| D | 服务器 30～60 元起 | 另需域名、HTTPS、运维与风控应对 |
| E | 0 元 | 开发与分发成本另计 |
