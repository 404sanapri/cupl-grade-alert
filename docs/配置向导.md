# 配置向导（面向第一次用 GitHub 的同学）

全程只需要点鼠标，不写代码。预计 10 分钟。

> ⚠️ **先看这条**：本向导写的是「把仓库放到 GitHub 上跑 + 群机器人收通知」的流程。
> 2026-11-06 实测发现境外 runner 访问教务系统 `jwxt:80` 一律超时，
> **定时检查已经改到本机跑**，个人提醒也改成了**电脑通知**（不需要机器人）。
> 请优先看 [本机计划任务.md](本机计划任务.md) 与 [桌面版.md](桌面版.md)。
> 本文仍适用于：想让公告广播跑在 Actions 上、或想留一份仓库备份的情况。

---

## 第 0 步：确认密码

本项目的密码是 **智慧法大统一认证** 的密码，不是教务系统单独的本地密码。

先打开 <https://ca.cupl.edu.cn>，用学号密码登录一次，确认能进「智慧法大」首页。
如果登录不进去，后面的步骤都不会成功——先去「忘记密码」重置。

> 强烈建议：如果密码还是学号，先改掉再用。

---

## 第 1 步：复制仓库

1. 打开项目主页。
2. 右上角 **Use this template** → **Create a new repository**。
3. 填个名字（例如 `my-grade-alert`），可见性选 **Public**（免费且额度不限）。
4. 点 **Create repository**。

> 用 Fork 也可以，但 template 仓库后续升级更干净。

---

## 第 2 步：建群机器人

### 钉钉

1. 打开要接收通知的群 → 右上角设置 → **机器人** → **添加机器人**。
2. 选 **自定义**（通过 Webhook 接入）。
3. 安全设置勾选 **加签**，复制两样东西：
   - `Webhook`：`https://oapi.dingtalk.com/robot/send?access_token=...`
   - 签名密钥：`SEC` 开头的一长串
4. 完成添加。

### 飞书

1. 群设置 → **群机器人** → **添加机器人** → **自定义机器人**。
2. 安全设置勾选 **签名校验**，复制 Webhook 与密钥。
3. 完成添加。

### 如果不想用加签

安全设置里选 **自定义关键词**，关键词填：`成绩`。

本项目发出的每条消息都包含「成绩」二字，所以一定能通过校验。

**不要选 IP 白名单**：GitHub Actions 的出口 IP 每天都不一样，白名单必然失效。

---

## 第 3 步：填 Secrets

进入你刚创建的仓库：

**Settings → Secrets and variables → Actions → New repository secret**

依次添加 5 个（名称必须完全一致，区分大小写）：

| Name | Secret 值 |
| --- | --- |
| `CUPL_USERNAME` | 你的学号 |
| `CUPL_PASSWORD` | 智慧法大的密码 |
| `NOTIFY_CHANNEL` | `dingtalk` 或 `feishu`（全小写） |
| `NOTIFY_WEBHOOK` | 第 2 步复制的 Webhook |
| `NOTIFY_SECRET` | 加签密钥；用关键词校验时留空不填 |

> Secret 一旦保存就无法再查看，只能覆盖。填错了重新 New 一个同名 Secret 即可。
> 这些值不会出现在日志里，也不会被 fork 出去的人看到。

---

## 第 4 步：启用并测试

### 4.1 启用 Actions

点仓库顶部 **Actions** 标签页。第一次会看到提示：

> Workflows aren't being run on this forked repository

点绿色按钮 **I understand my workflows, go ahead and enable them**。

### 4.2 先跑 dry-run

1. 左侧点 **成绩更新监控**。
2. 右侧 **Run workflow** → 勾选 **只验证登录与解析** → **Run workflow**。
3. 等 30 秒左右，点进这次运行，展开 **执行成绩检查**。

看到下面这行就说明账密与接口都正常：

```
INFO 解析到 45 条成绩
INFO 首次运行：建立基线 45 条，本次不推送
```

### 4.3 测通知

如果 dry-run 通过，再跑一次 **Run workflow**（**不要**勾 dry-run）。

这次会写入基线并开始监控。之后每 10 分钟自动检查一次。

想立刻确认群机器人是否配好，可以在本机执行：

```powershell
python src\monitor.py --test-notify
```

或在 Actions 里把 `NOTIFY_*` 配好后，等第一次真实新增成绩。

## 常见卡点

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 日志报 `ConfigError: 缺少 CUPL_USERNAME` | Secret 名字拼错或没加 | 检查大小写，重新创建 |
| 日志报 `统一认证登录失败：用户名或密码错误` | 密码不是统一认证的，或已修改 | 去 ca.cupl.edu.cn 验证 |
| 日志报 `已启用通知渠道但缺少 NOTIFY_WEBHOOK` | Secret 缺失 | 补上，或用 dry-run |
| Actions 里没有「成绩更新监控」 | workflow 未启用 | 点 Actions 页的启用按钮 |
| 到了时间但没运行 | GitHub 排队延迟 / 仓库 60 天无活动被暂停 | 手动 Run 一次，或提交一次 commit 唤醒 |
| 群里收不到消息 | 加签密钥错、关键词不匹配、机器人被移出群 | 用 `--test-notify` 排查 |

更多见 [故障排查与回退.md](故障排查与回退.md)。
